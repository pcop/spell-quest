# 拼字冒險王 🌈

一個給學齡前～國小低年級兒童玩的英文拼字練習遊戲。純前端 HTML5 網頁，沒有後端、沒有帳號系統，開啟網頁就能玩。

## 功能

- **綜合提示模式**：圖片（emoji / 色塊）＋ 發音（瀏覽器語音朗讀）＋ 拖曳、點擊或鍵盤排列字母，可在關卡選擇畫面切換要用哪種提示
- **7 個主題**：動物、顏色、數字、水果、日常物品、身體部位、其他；前 6 個主題各自 × 3 個難度，難度依單字字母長度分初級（3 字母）／中級（4 字母）／高級（5+ 字母）。「其他」主題則改用**自訂關卡**（見下方「新增/修改單字內容」），關卡是手動指定的一批單字（可混合各種字母長度），不吃長度分級規則，目前只有一關「暑假複習1」
- **中文提示**：拼字關卡的題目除了圖片/色塊，現在也會同時顯示中文意思（例如 🏞️ 旁邊顯示「湖泊」），避免 emoji 意思不夠清楚時孩子猜不出圖片在畫什麼；只跟著「圖片」提示模式一起顯示/隱藏，純聽音模式（🔊 發音）不會顯示中文，維持只能靠聽的挑戰。字卡瀏覽、拼讀練習畫面本來就會顯示完整拼法文字，不需要另外加中文
- **提示安全閥**：卡關時可按 💡 提示鈕，自動填入下一個字母，每題限用一次，用過會影響該題星等（避免變成直接看答案）
- **發音速度調整**：🐢 慢速／🚶 正常／🐇 快速，切換時會立即試聽
- **音效開關**：可關閉答對/答錯的合成音效
- **闖關進度紀錄**：用瀏覽器 `localStorage` 記錄每個主題×難度的星等、正確率，並可匯出/匯入 JSON 進度檔換裝置使用
- **3D 慶祝特效（拼字關卡的硬性需求）**：答對用 three.js 粒子特效（彩帶雨／煙火隨機輪替）；過關用手刻的低多邊形 3D 模型展示——一般過關是「獎盃／禮物盒」隨機旋轉展示，該關卡首次拿到 3 顆星時則播放專屬的「開寶箱」動畫並掉出一張貼紙。three.js 是拼字關卡的**硬性需求**，不是裝飾性強化：CDN 連不上或裝置不支援 WebGL 時，主選單「開始遊戲」按鈕會被鎖住並顯示原因，拼字關卡進不去；字卡瀏覽、拼讀練習、進度頁完全不依賴 three.js，不受影響仍可正常使用
- **貼紙收藏**：每個「主題×難度」組合首次拿到 3 顆星，就能在過關時開寶箱獲得一張對應主題的貼紙，「我的進度」頁面新增貼紙簿可以回顧收集進度；貼紙記錄併入既有的 `localStorage` 進度物件，會自動包含在匯出/匯入功能裡
- **音節分組視覺輔助**：多音節單字（例如 `apple`、`banana`）的答案槽位會依音節分組加大間距＋交替淡色底色，幫助孩子理解單字結構；純視覺輔助，排列/判分機制不變，單音節單字不受影響
- **字卡瀏覽（學習模式）**：不計分、不記錄進度的單字瀏覽功能，固定同時顯示圖片＋完整拼法＋發音。兩個入口：選難度畫面的 📖 按鈕（範圍鎖定該主題＋該難度）、主選單的「📖 單字字卡」（選一個主題後瀏覽該主題全部單字，不分難度）。多音節單字（有 `syllables` 資料的那 17 個字）會在拼法下方多顯示一行用連字號分隔的音節提示（例如 `ap-ple`），主要拼法本身維持正確、不帶連字號；單音節單字不會有這行。切換卡片除了點擊「◀ 上一個／下一個 ▶」按鈕，也支援鍵盤方向鍵（← 上一張／→ 下一張），已經是第一張/最後一張時方向鍵一樣沒有反應（跟按鈕的 disabled 狀態一致，兩者共用同一套判斷）
- **自然發音（Phonics）拆解**：全部 97 個單字都有 `phonics` 音素拆解資料（跟音節資料是不同的一份，音節管拍數、這份管字母怎麼發音）。字卡瀏覽畫面新增 🔤 按鈕與音素拆解提示行（例如 `c-a-t`，不發音的字母如 silent e 會用括號淡化標示），按下後逐段播放每個字母/字母組合的近似發音，最後唸出完整單字
- **拼讀練習（學習模式，🎧）**：主選單獨立入口，選一個主題後開始無限隨機練習，不計分、不記錄進度。每題播放單字的自然發音拆解，畫面顯示 3 個候選單字（圖片＋文字，1 對 2 錯，干擾選項來自同主題），聽音辨字選出正確答案；答錯只是排除該選項、可以繼續嘗試，沒有懲罰
- **過關/答對動畫多樣化**：星星改成逐顆蹦出＋音效，不再是一次性顯示文字。答對的即時回饋維持輕量（不拖慢拼字節奏），只在吉祥物動畫（彈跳／搖擺）與 3D 粒子樣式（彩帶雨／煙火，只用這兩種較低調的）之間做小變化。過關則用獎盃／禮物盒／寶箱三種 3D 模型分層呈現強度（見上方「3D 慶祝特效」）。鼓勵文案池也擴充了
- **答對後停在原題目，手動切下一題**：答對不再自動倒數（原本 1.2 秒後自動跳題），而是停在原題目讓孩子看清楚正確拼法／星等回饋，畫面下方會出現「▶️ 下一題」按鈕，按下該按鈕或按空白鍵才會前進到下一題（最後一題則直接進結果畫面）。停留期間拼字關卡維持鎖定（跟原本答對後到自動跳題前的那段鎖定狀態一樣），字母方塊/答案槽位不會回應點擊或鍵盤輸入，但 🔊 發音按鈕仍可按來重聽單字。答錯的行為沒有變，還是 0.5 秒後自動清空重試，不需要手動確認
- **3D 特效診斷工具**：「我的進度」頁面新增「🔍 檢查 3D 特效狀態」，直接讀 `window.ThreeFX` 是否存在（不透過容易誤判的事件/timeout 偵測），可用時會立即觸發一次真實的過關展示特效讓你親眼確認

## 快速開始

專案會用 `fetch` 讀取 `data.json`，**必須透過網頁伺服器開啟**，不能直接雙擊 `index.html`（`file://` 協定下 `fetch` 讀本機檔案會失敗）。

```bash
cd 拼字遊戲
python3 -m http.server 8000
# 或使用 npx serve
```

然後用瀏覽器開啟 `http://localhost:8000`。

## 檔案結構

```
拼字遊戲/
├── index.html   # 頁面骨架，各畫面的 <section> 容器，含 three.js 的 importmap
├── styles.css   # 色彩系統、動畫、RWD/觸控樣式
├── data.json    # 單字庫（wordBank）＋ 主題（themes）＋ 難度規則（difficultyTiers）
├── app.js       # 遊戲邏輯：資料載入、畫面切換、出題、判分、語音、進度儲存、自然發音拆解＋拼讀練習
├── three-fx.js  # 3D 特效層（ES module）：拼字關卡的答對/過關特效都靠它，是硬性需求；
│                # 失敗時只會鎖住拼字關卡，字卡瀏覽/拼讀練習/進度頁不受影響
├── phonics-audio/               # 自然發音音素音檔（53 個 .mp3，檔名＝chunk 文字，例如 th.mp3）
└── tools/
    └── generate-phonics-audio.sh  # 產生 phonics-audio/ 的腳本，新增字用到新 chunk 時重跑這支
```

沒有建置工具；`app.js` 是單一 IIFE，用原生 DOM API 操作畫面，沒有外部依賴。`three-fx.js` 是唯一的例外——透過 `index.html` 的 `<script type="importmap">` 從 CDN（jsdelivr）載入 three.js 的 ES module 版本。**three.js 是拼字關卡的硬性需求，不是裝飾性強化**：CDN 連不上或瀏覽器不支援 WebGL 時，主選單「開始遊戲」按鈕會被鎖住、拼字關卡進不去；但字卡瀏覽、拼讀練習、進度頁（含貼紙簿）完全不依賴 three.js，照樣完整可用。

## 遊戲流程

主選單 → 選主題 → 選難度（可調整提示模式/音效/發音速度）→ 遊戲畫面（依序拼完該難度所有單字）→ 結果畫面（星等＋鼓勵文案）→ 可選擇再玩一次／換難度／回主選單。「我的進度」頁面可看到所有主題×難度的星等總覽，並提供進度匯出/匯入。

## 新增/修改單字內容

單字庫全部寫死在 `data.json`，直接編輯即可，不需要改程式碼：

```json
{ "id": "animal_cat", "word": "cat", "theme": "animals", "emoji": "🐱", "zh": "貓" }
```

- `id`：唯一識別碼，格式建議 `主題_單字`
- `word`：英文單字（小寫），長度決定難度（3 字母＝初級／4＝中級／5+＝高級）
- `theme`：對應 `themes` 陣列裡的主題 `id`
- `emoji`：用來當圖片提示的 emoji；若找不到合適的 emoji（例如顏色類單字），改用 `"emoji": null` 搭配 `"swatch": "#hex色碼"` 顯示色塊
- `zh`（必填）：這個單字的中文意思，例如 `"turtle"` 對應 `"烏龜"`。拼字關卡的題目在「圖片」提示模式下會把它顯示在圖片/色塊下方，用來補強 emoji 意思不夠精準的情況（尤其是動詞或抽象概念，emoji 常常畫不清楚，例如 `bake`、`crawl`）；純聽音模式不會顯示
- `syllables`（選填）：多音節單字的音節拆分，例如 `"syllables": ["ap", "ple"]`；陣列串接後必須完全等於 `word`。只有多音節單字需要加這個欄位，單音節單字（`cat`、`red`⋯）不用加，答案槽位不會顯示分組
- `phonics`（必填）：自然發音的字母/字母組合拆解，例如 `"phonics": { "chunks": ["c", "a", "t"], "silent": [] }`；`chunks` 陣列串接後必須完全等於 `word`，`silent` 是不發音字母（例如 silent e）在 `chunks` 裡的索引（0 起算）。拆解規則：子音群（ch/sh/th/ck/wh/nk）、母音團（ee/ea/oo/ow/ou/ay/ue/eigh/oa/aw）、r controlled 母音（ar/er/ir/or/ur/air/ear/our/oor）、重複字母（ll/rr/pp）各算一個 chunk；子音團（blend，例如 br/pl/st）維持拆成個別字母，因為它們是兩個音快速連在一起、不是一個音。**新增單字如果用到現有 53 個 chunk 之外的新組合，要在 `tools/generate-phonics-audio.sh` 的對照表補一行、重新執行這支腳本產生對應的 `phonics-audio/<chunk>.mp3`**——`phonics.chunks` 只是資料，實際播放的音檔要另外生成，不會自動生效。同一個 chunk 文字只會對應一種發音，如果同樣的拼法在不同單字裡唸法不同（例如字尾 `y` 在單音節字唸長 i、多音節字唸長 e），只能取一個代表音，是已知限制不是 bug（跟 `oo`／`ear` 那幾個 chunk 的取捨一樣）

新增主題則在 `themes` 陣列加一筆 `{ id, name, icon, color }`；這個主題會自動套用全站共用的長度分級規則（`difficultyTiers`：初級/中級/高級）。

**自訂關卡（跳脫長度分級）**：如果想要一個像「暑假複習1」這樣自己指定單字清單、不受長度分級限制的關卡，在主題物件上加一個 `customLevels` 陣列即可，該主題就會完全改用這份清單、不再套用 `difficultyTiers`：

```json
{ "id": "other", "name": "其他", "icon": "🧩", "color": "#9b5de5",
  "customLevels": [
    { "id": "summer_review_1", "label": "暑假複習1", "distractorCount": 2, "wordIds": ["other_cake", "other_turtle"] }
  ]
}
```

- `id`：這個關卡的唯一識別碼（在該主題內不重複即可），會被當成內部的關卡 key（等同原本的 `tier`），進度會記在 `levels['<themeId>_<id>']` 底下
- `label`：關卡選擇畫面顯示的名稱
- `distractorCount`（選填，預設 2）：字母拼盤要混入幾個干擾字母；因為自訂關卡通常混合各種單字長度，沒有像 `difficultyTiers` 那樣依長度自動決定的規則，要自己指定
- `wordIds`：這個關卡包含哪些單字，直接列 `wordBank` 裡的 `id`（可以跨長度混合），出題順序會被洗牌但清單本身照你填的順序做字卡預覽
- 一個主題要嘛完全用 `customLevels`、要嘛完全用 `difficultyTiers` 自動分級，同一個主題目前不支援兩者混用；同一主題可以放多個 `customLevels`（例如之後再加「暑假複習2」）

**注意**：`app.js` 裡的 `MIN_WORDS_PER_LEVEL`（目前為 3）會讓單字數不足的關卡自動停用，所以不論是走長度分級還是自訂關卡，同一個關卡至少要湊到 3 個單字才會開放。

## 進度資料格式

儲存在 `localStorage` 的 `spelling_game_progress_v1`：

```json
{
  "schemaVersion": 1,
  "settings": { "hintMode": "both", "soundEnabled": true, "speechRate": 0.8 },
  "levels": {
    "animals_1": {
      "themeId": "animals", "tier": 1,
      "attempts": 12, "correctCount": 10,
      "bestAccuracy": 0.92, "bestStars": 3, "completed": true,
      "wordProgress": { "animal_cat": { "correct": 3, "wrong": 0 } }
    }
  },
  "collectibles": { "animals_1": true }
}
```

每答完一題就即時寫入，重新整理頁面不會遺失進度；星等只升不降。`collectibles` 記錄哪些「主題×難度」組合已經開過寶箱拿到貼紙（key 跟 `levels` 用同一套 `themeId_tier` 格式），只有該組合**首次**拿到 3 顆星時會寫入一次，之後重複拿 3 星不會重複觸發。舊版進度檔（這個欄位還不存在前存的）匯入/讀取時會自動補一個空物件，不需要升級 `schemaVersion`。「我的進度」頁面的「匯出進度」會下載這份 JSON，「匯入進度」可讀回並覆蓋目前的進度（會做基本格式驗證，格式不符會拒絕匯入以避免洗掉既有進度）。

## 瀏覽器相容性備註

- 發音朗讀依賴瀏覽器原生 `SpeechSynthesis`，若裝置沒有安裝英文語音，喇叭與自動朗讀會自動隱藏，不影響其他功能
- 行動裝置上第一次進入遊戲需要先點擊「開始遊戲」按鈕，才能解鎖語音與音效的播放權限（瀏覽器的自動播放限制）
- 字母排列同時支援點擊（主要互動）、觸控拖曳（輔助互動，沒有使用 HTML5 Drag and Drop API，以確保觸控裝置可正常遊玩）與鍵盤輸入（第三種並行的輸入方式）：拼字關卡畫面顯示時，按對應的字母鍵會自動填到目前拼盤裡「未使用」且字母相符的方塊（跟點擊那顆方塊效果完全一樣，重複字母的話挑哪一個未用方塊都可以，因為方塊本身除了字母沒有其他差異）；Backspace／Delete 會刪掉目前最後一個已填的格子（格子固定由左往右依序填入，所以「最後一個已填格」就是「最後輸入的字母」）；答對後停在原題目等待確認時，空白鍵等同按下畫面上的「▶️ 下一題」按鈕（見下方「答對後停在原題目」）。不需要先點擊/focus 任何元素，只要拼字關卡畫面正顯示就會生效；已提示的格子跟滑鼠點擊移除一樣沒辦法用 Backspace 刪掉
- **3D 特效是拼字關卡的硬性需求**，需要瀏覽器支援 `<script type="importmap">`（Chrome/Edge 89+、Safari 16.4+、Firefox 108+）與 WebGL。App 一啟動就會判斷 three.js 是否成功初始化：判斷完成前主選單「開始遊戲」按鈕顯示「準備中...」並停用；成功則按鈕恢復正常，失敗則按鈕永久停用並顯示「此裝置不支援」的說明文字（`title` 提示完整原因）。這個判斷**只影響拼字關卡**，字卡瀏覽、拼讀練習、進度頁（含貼紙簿）完全不受影響，隨時可用。之前版本會用 `localStorage` 記一個旗標讓失敗提示只跳一次 toast，這次拿掉了——按鈕本身的停用狀態就是持續可見的提示，不需要額外的一次性 toast
  - **已修過的 bug（偵測時序）**：這個偵測邏輯原本有時序競爭問題——監聽 `threefx-ready`/`threefx-error` 事件的程式碼包在 `DOMContentLoaded` 裡才註冊，但 `three-fx.js` 是 `<script type="module">`（行為等同 defer），通常會在 `DOMContentLoaded` 觸發「之前」就執行完畢並送出事件，導致監聽器永遠接不到、被 9 秒保底 timeout 誤判成失敗，即使 three.js 其實成功初始化了。現在已經把監聽器移到同步執行的地方、搶在 three-fx.js 執行前註冊
  - **已修過的 bug（粒子太不明顯）**：根本原因是 `THREE.PointsMaterial` 預設的 `sizeAttenuation: true`——這個「距離越遠越小」的縮放公式是為透視相機設計的，但這裡用的是正交相機、座標空間直接對應螢幕像素，套用這個公式會讓算出來的粒子尺寸遠比預期小很多。已關閉 `sizeAttenuation` 並把基礎尺寸從 16 加大到 40，並讓尺寸乘上 `renderer.getPixelRatio()`（`sizeAttenuation:false` 時 `size` 是 framebuffer 像素、不是 CSS 像素，不乘 pixelRatio 的話同一數值在 2x 視網膜螢幕上會只有 1x 螢幕的一半大，兩台裝置看起來明顯不一樣大）；獎盃/禮物盒/寶箱這幾個實體 3D 模型的尺寸也是同一個陷阱，全部落在 100~300 這個「像素單位」範圍內手刻，不是常見的 1 這種三維軟體單位
  - **過關特效全面改成純 three.js（不再有 CSS 備援）**：答對維持 three.js 粒子（彩帶雨／煙火隨機輪替，不用星星爆發那種大場面）；過關則從粒子特效改成手刻的低多邊形 3D 模型——一般過關在「獎盃／禮物盒」間隨機展示、緩慢旋轉；該關卡首次拿到 3 顆星時，改播放專屬的「開寶箱」動畫（蓋子掀開後透過回呼通知 `app.js` 彈出貼紙揭曉視窗），之後同一關再過關就回到一般展示，不會重複開寶箱。原本 CSS confetti 的備援程式碼（`spawnConfetti`／`CONFETTI_STYLES` 與對應的 CSS keyframes）已經整個移除，不是留著備用
  - **3D 模型會用實體光源**：粒子系統用的 `PointsMaterial` 不吃光源，但過關模型用 `MeshStandardMaterial` 才有立體明暗，所以場景新增了 `AmbientLight` + `DirectionalLight`，這是加模型才需要補的東西
  - **結果畫面的疊層順序**：`#three-fx-layer` 是 `position:fixed` 的定位元素，畫面上會蓋在一般排版的 `.panel` 之上（CSS 疊層順序跟定位/z-index 有關、跟 DOM 順序無關）。過關的 3D 模型是不透明實體，直接蓋在結果面板上會擋住星星和文字，所以把 `.result-panel` 也設成有 `z-index` 的定位元素、疊在特效層之上——模型超出面板範圍的部分還是看得到，面板覆蓋到的地方會蓋掉模型，不會擋住文字
  - **中途離開結果畫面要取消特效**：如果孩子在開寶箱動畫播完（蓋子打開）之前就點了「再玩一次」／「選其他難度」／「回主選單」，`window.ThreeFX.cancelCelebration()` 會清掉還在播放的模型，確保還沒觸發的貼紙揭曉回呼永遠不會在下一個畫面上憑空跳出來
- **發音系統全面採用高品質神經網路真人語音（Microsoft Edge Neural Voice / `en-US-JennyNeural`）**：
  - **單字朗讀（`words-audio/`）**：全題庫單字（89 個單字）皆預先生成高品質美式真人女聲 MP3 音檔，音質溫暖自然、清晰生動，並支援 `playbackRate` 慢速播放。若音檔載入異常自動無縫降級至瀏覽器 `SpeechSynthesis`。
  - **自然拼讀逐音播放（`phonics-audio/`）**：53 個自然發音音素（Phonics Chunks）全面以自然發音教學詞進行高精度截取與靜音修整，徹底解決傳統 TTS 拼讀生硬與機械感問題。
  - **智慧預載入（Preload）**：切換關卡、字卡與題目時自動在背景預載入所需音訊，達到點擊即時發音、零延遲的極致體驗。
  - **全裝置相容**：無論使用電腦、手機、平板或 Linux，發音效果 100% 完全一致，不再受各裝置系統語音庫缺失影響。
